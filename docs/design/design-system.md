# 9Router design system

The operational avant-garde language for 9Router. This document is the
authority. Where a component and this document disagree, the component is
wrong.

Every ratio in the contrast tables below is generated by
`docs/design/verification/contrast.mjs`, which resolves the live values out of
`src/app/globals.css` and measures them. Nothing here is asserted by hand. The
pair list is `docs/design/tokens.pairs.json`. Regenerate after changing a token
with

```
node docs/design/verification/contrast.mjs --markdown
```

## 1. Foundation

Near-black and mineral white, one electric operational accent, a small
semantic set. The two themes are authored independently. Dark is not an
inversion of light, and several tokens deliberately behave differently in each,
which is called out where it happens.

The accent is a teal-cyan. On the mineral-white ground it appears as a deep
step (`#00786C`) carrying white. On the near-black ground it appears as the
bright step (`#2FE0CD`) carrying dark ink (`#04211E`). One accent, two
treatments, because a single value cannot be both electric on black and legible
on white.

Colour carries state, urgency, selection and flow. It never fills space. A
region is not tinted to look designed.

### Token roles

| Role | Token | Meaning |
|---|---|---|
| Ground | `--color-bg` | The page itself |
| Ground, alternate | `--color-bg-alt` | Bands and rails that sit on the ground |
| Raised | `--color-surface` | A surface holding content |
| Inset | `--color-surface-2` | A region pushed into a surface |
| Sunken | `--color-surface-3` | The deepest inset, used for wells and code |
| Line | `--color-border` | Structural separation |
| Line, subtle | `--color-border-subtle` | Rhythm inside a group |
| Text | `--color-text` | Primary reading weight |
| Text, secondary | `--color-text-muted` | Labels and support |
| Text, tertiary | `--color-text-subtle` | Metadata, never load bearing |
| Accent | `--color-brand` | Accent at text weight |
| Accent, solid | `--color-brand-solid` | Filled accent control |
| Accent, label | `--color-brand-on` | Label on a filled accent control |
| Accent, soft | `--color-brand-soft` | Accent field |
| Accent, line | `--color-brand-line` | Accent boundary |

Each status (`danger`, `warning`, `success`, `info`) carries the same five
slots as the accent, so a status and a primary action are expressed the same
way and can be swapped without re-learning the grammar.

### The hover invariant

A hovered control never lowers the contrast of its own label. In the light
theme the accent fill is dark and the label is white, so the hover step
darkens. In the dark theme the accent fill is bright and the label is dark ink,
so the hover step lightens. Both obey the invariant; the direction differs
because the themes are authored independently. An alpha-based hover is
forbidden, since blending toward whatever sits behind the control lowers label
contrast exactly when the pointer is on it.

### Status is never carried by hue alone

Every status token pairs with a glyph and a word. A dot, a triangle and a
hollow circle distinguish healthy, degraded and idle without reference to
colour. A status that reads only as a colour is a defect: every small saturated
element must carry text, an icon or an accessible name.

## 2. Typography

Three roles, no more.

| Role | Family | Used for |
|---|---|---|
| Display | Inter Tight, falling back to Inter and the system sans | Headings, orientation, the one large number that answers the screen |
| Interface | Inter, falling back to the system sans | Everything a person reads as prose or a label |
| Technical | JetBrains Mono, falling back to the platform mono | Identifiers, endpoints, model names, tokens, telemetry, every quantity |

Rules that are not negotiable.

Quantities use tabular numerals, always, so a column of numbers aligns and a
changing readout does not jitter. Identifiers, endpoints, model names and error
codes are set in the technical face, because they are strings a person will
copy rather than read. Large type is reserved for meaningful state or
orientation. A large number that is decorative is a defect. Body text is never
below 12.5 pixels, and the technical face is never below 10.5 pixels, which is
its legibility floor at these weights.

The eyebrow, a mono label at 10 pixels with wide tracking and upper case, is
the one permitted use of upper case. It marks a region, never a sentence.

## 3. Grid, spacing and density

The spacing scale is 4, 6, 8, 12, 16, 22, 32, 48. Nothing between.

Three densities, chosen by what the surface is for.

| Density | Row height | Where |
|---|---|---|
| Observation | 30 to 34 pixels | Tables, matrices, live readouts, anywhere scanning beats reading |
| Configuration | 40 to 44 pixels | Forms and sequential setup, quieter and more generous |
| Marketing | 56 pixels and up | Landing, spacious but concrete |

Controls sit on a 4 pixel baseline. A control that lands off the baseline is a
defect, not a style choice.

## 4. Structure instead of card chrome

Grouping is done with rules, bands, inset regions, rhythm and alignment.

A card is reserved for a genuinely portable object, something that could be
picked up and dropped somewhere else and still make sense. An API key is a
card. A page section is not. Radius is 3 pixels, effectively rectilinear, so a
rounded rectangle stops reading as the default container.

Elevation is expressed by ground, line and inset, not by shadow. One shadow
token remains, a single hairline for a genuinely floating layer such as a modal
or a popover. Ambient drop shadows on static regions are removed.

## 5. Motion

Motion explains transfer and nothing else. A route change, a context entry, a
status resolving. Duration is 120 to 180 milliseconds, easing is a standard
ease-out, and every transition is interruptible.

Under `prefers-reduced-motion` all movement and all transitions collapse to
zero duration. No animation ever delays work; a control is usable on the frame
it appears.

## 6. Focus and hit targets

Focus is a solid two-colour ring, a ground-coloured separator with the accent
ring on top, so it is visible on any surface. It is never removed without a
replacement that paints an indicator. Every focusable element is measured for
this by the audit.

Minimum hit target is 32 pixels on pointer surfaces and 44 pixels on phones.

## 7. Iconography

One family, Material Symbols, at a single optical weight. Icons are ligature
based, so their glyph text must be stripped before any accessible name is
computed, and every icon-only control carries a translated accessible name.
Icons support a label; an icon alone is only permitted where the accessible
name is present and the meaning is conventional.

## 8. Data visualisation grammar

A chart earns its place by answering a question that a number cannot. There are
no decorative charts.

Series use the accent for the subject and neutral steps for context. Status
colour appears in a chart only where the chart is about status. Axes are lines,
not boxes. A sparkline carries its current value as text beside it, because a
line without a number cannot be read precisely.

A multi-series chart draws from `--color-chart-1` through `--color-chart-6`,
which sit outside the status set so a series is never misread as a state. The
order is slate, indigo, teal, blue, fuchsia, amber, chosen so neighbouring
series stay separable under deuteranopia. Each slot carries 4.5:1 against the
surface it is drawn on, in both themes, because the legend renders the series
name as 12px text in the series colour rather than as a swatch beside neutral
text. That is a text requirement, not the 3:1 a bare stroke would need. The two
themes are authored independently here as everywhere else: the light steps are
unreadable on the dark ground and the dark steps wash out on the light one.

The bar, used for quota headroom and share, is a single rule with a filled
portion, not a rounded pill. Its track is the inset ground so the filled
portion reads as material rather than as decoration.

## 9. Asymmetry and alignment

Asymmetry is permitted, and wanted, at page scale. Offset columns, unequal
split panes, an anchored rail against an open canvas, a masthead that is dense
on one side and quiet on the other.

Alignment is mandatory everywhere below that. Inside any region, every control,
baseline, table column and readout sits on the shared grid. The composition is
deliberately unbalanced; the contents are strictly ordered. Loose alignment
inside an asymmetric layout reads as an accident rather than a decision.

## 10. How desktop recomposes on phones

The shell is a masthead, a rail and a workspace.

At laptop width the rail narrows and the workspace keeps both panes.

At phone width the rail becomes a bottom-anchored bar carrying the four jobs,
the masthead collapses to a single line of the two readouts that change
decisions (throughput and error rate) plus the degraded count, and the two
workspace panes stack with the pane carrying the focal answer first. A
contextual pane becomes a sheet reached by one action from the row it belongs
to, never more.

Nothing is dropped on the way down. A control that exists at 1440 exists at
390, at most one disclosure away, which is measured by the capability
inventory.

## 11. Localisation as a layout constraint

Containers are sized to their content, never to English. Translated labels wrap
rather than truncate, and `whitespace-nowrap` is not applied to a translated
string. The only permitted truncation is of a value that appears in full
elsewhere on the same screen, such as a key or a long identifier.

German and Vietnamese are the length stress cases, Chinese and Japanese the
density cases. Persian is the right-to-left case and its current behaviour is
recorded in the localisation report rather than assumed.
